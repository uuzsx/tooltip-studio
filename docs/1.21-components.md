# Minecraft 1.21.1～1.21.4：组件匹配与旧配置迁移

Tooltip Studio 1.9.0 分别提供 1.20.4、1.21.1、1.21.2、1.21.3、1.21.4 的 Fabric JAR。只安装与你的 Minecraft 版本一致的一个文件，并安装对应版本 Fabric API。1.21.x 使用 Java 21，Fabric Loader 至少 0.16.14。1.20.4 仍可用 Java 17。

物品数据组件实际从 Minecraft 1.20.5 引入。自定义 NBT 没有消失，而是通常存放到 `minecraft:custom_data` 组件中。模组只读取客户端收到的数据；服务器没有发送的字段无法匹配。

## 朋友的 Monumenta 规则需要重写吗？

如果服务器把原来的自定义字段保留在 `minecraft:custom_data` 内，原来的规则可以直接继续用：

```json
{
  "schemaVersion": 1,
  "rules": [
    {
      "style": "monumenta/forest",
      "priority": 300,
      "nbt": { "Monumenta.Location": "forest" }
    }
  ]
}
```

`nbt` 在 1.20.4 读取物品的 `tag`，在 1.21.1～1.21.4 读取 `minecraft:custom_data`。路径仍然从 `Monumenta` 开始，不加 `SelectedItem`、`tag` 或 `components` 前缀。上述样式 ID 需要已有对应的样式文件。

`nbtStyleKey` 也继续生效：默认读取 `custom_data` 根节点内的字符串 `TooltipStyle`，用来指定样式。名称、Lore、耐久、附魔等原版字段已迁入各自的组件，不能继续假设它们还在旧 `display`、`Damage`、`Enchantments` 路径下。

## 新的 components 写法

`rules` 和 `decorationRules` 都支持可选的 `components`，例如：

```json
{
  "schemaVersion": 1,
  "rules": [
    {
      "style": "monumenta/forest",
      "priority": 300,
      "items": ["minecraft:diamond_sword"],
      "components": {
        "minecraft:custom_data": { "Monumenta.Location": "forest" },
        "minecraft:rarity": ["rare", "epic"],
        "minecraft:damage": 7
      }
    }
  ]
}
```

- 组件 ID 写完整的命名空间，如 `minecraft:rarity`、`some_mod:quality`，并区分大小写。
- 组件整体是一个数字、字符串或布尔值时，直接写值。数组表示任选一个候选值。
- 组件包含结构化数据时，写一个“内部路径 → 期望值”的对象，如 `"Monumenta.Location": "forest"`。路径语法与 `nbt` 一样，支持列表下标及带引号的键名。
- 多个组件、多个路径，以及 `items` / `tags` / `rarities` / `nbt` / `components` 之间都需要同时满足。同一候选数组内部任选其一。
- 数字 `7` 与字符串 `"7"` 不相同。组件不存在或路径不存在时不匹配。物品自带的默认组件也参与匹配。
- 匹配的是组件自身保存时的编码内容，字段名称以该 Minecraft / 模组版本为准；例如 `custom_model_data` 在 1.21.4 与 1.21.1 的结构不同。
- 支持已安装模组注册、可持久化编码的组件。未知组件 ID 或无持久化编码的组件会使本次重载失败，保留之前的有效配置；组件无法在当前上下文编码时按不匹配处理。
- 1.20.4 没有数据组件，不能使用 `components` 条件；该版本会明确报错，不会把条件忽略成全匹配。

## 先用一把剑试试

先启用对应版本的 `tooltip-studio-component-pack-1.9.0+你的版本.zip`，然后在允许命令的世界执行：

```mcfunction
/give @s minecraft:diamond_sword[minecraft:custom_data={Monumenta:{Location:"forest",Tier:"artifact"}},minecraft:rarity="epic",minecraft:damage=7]
```

鼠标移到剑上：基础样式保持默认款，并额外显示两种颜色拼合的文字装饰。把 `epic` 改成 `rare`，文字装饰不再匹配；`Monumenta.Location` 仍然能触发旧 `nbt` 规则。

查看实际数据（有命令权限时）：

```mcfunction
/data get entity @s SelectedItem.components
/data get entity @s SelectedItem.components."minecraft:custom_data".Monumenta.Location
```

修改资源包后按 F3+T，或执行 `/tooltipstudio reload`。原来的样式、分割线、图片/文字装饰、动态 PNG、多段文本和偏移参数沿用原写法。

## 资源包版本

| Minecraft | pack.mcmeta 的 pack_format |
| --- | --- |
| 1.20.4 | 22 |
| 1.21.1 | 34 |
| 1.21.2、1.21.3 | 42 |
| 1.21.4 | 46 |

本项目打包出来的示例 ZIP 已使用对应格式。自己搬旧资源包时记得改 `pack_format`；旧的 `/give 物品{NBT}` 命令也需改成新版的方括号组件写法。

## 开发构建

构建工具使用 JDK 21 和 Gradle Wrapper 8.12.1。共用 `src/main`、`src/test`；`src/platform` 只放 Minecraft API 的版本差异，避免复制整套模组代码。

```sh
./gradlew buildAllVersions
./gradlew -Pmc=1.21.1 :mc1.21.1:build
./gradlew -Pmc=1.21.4 :mc1.21.4:runSmoke
```

根项目输出 1.20.4 到 `build/libs`；新版输出到 `versions/版本/build/libs`。`runSmoke` 是开发用的真实客户端测试，不会打入发布 JAR。

参考：[Fabric 1.20.5/1.20.6 数据组件迁移说明](https://fabricmc.net/2024/04/19/1205.html)。
